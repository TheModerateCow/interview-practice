## Level 2: hold expiry

Merchants don't always capture or void, and a hold can't lock up a customer's credit forever. Add:

| Method | Behaviour |
|---|---|
| `{{holds}}(day, card_id)` | The card's open authorisations as `"auth_id:amount"` (for example `"a3:2500"`), oldest first (in id order). An empty list if the card doesn't exist or has none. |
| `{{auth_status}}(day, auth_id)` | `"open"`, `"captured"`, `"voided"` or `"expired"`; `""` if the authorisation doesn't exist. A partly captured authorisation is `"captured"`. |

**Expiry.** An authorisation approved on day `d` that is still open at the start of day `d + 7` expires: from that day on it's `"expired"`, its hold is released (it no longer counts against `{{available}}` and isn't in `{{holds}}`), and `{{capture}}` and `{{void_auth}}` return `false` for it. On day `d + 6` it can still be captured. Captured and voided authorisations never expire.

### Example

```
issue_card(1, "c1", 10000)
authorize(1, "c1", "hotel", 2000)  -> "a1"
authorize(3, "c1", "fuel", 5000)   -> "a2"
holds(4, "c1")                     -> ["a1:2000", "a2:5000"]
available(7, "c1")                 -> 3000
available(8, "c1")                 -> 5000    (a1 expired on day 8)
holds(8, "c1")                     -> ["a2:5000"]
auth_status(8, "a1")               -> "expired"
capture(8, "a1", 2000)             -> false
```
