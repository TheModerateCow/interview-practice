## Level 3: refunds and statements

Customers return goods, and they want to see what was charged. Add:

| Method | Behaviour |
|---|---|
| `{{refund}}(day, auth_id, amount)` | The merchant refunds `amount` of a captured authorisation. A capture can be refunded in several parts, but the refunds together can never exceed the amount captured (not the amount authorised). Returns `false`, changing nothing, if the authorisation doesn't exist, isn't captured (open, voided or expired), or `amount` is `<= 0` or more than what is left to refund. |
| `{{balance}}(day, card_id)` | What the customer owes: everything posted (captures minus refunds). Holds don't count. `-1` if the card doesn't exist. |
| `{{statement}}(day, card_id)` | The card's posted entries in the order they happened: a capture as `"day:auth_id:charge:amount"`, a refund as `"day:auth_id:refund:amount"`, where `day` is the day of the capture or refund. Holds, voids and expiries don't appear. An empty list if the card doesn't exist. |

A refund lowers the posted total, so it gives that credit back to `{{available}}`.

### Example

```
issue_card(1, "c1", 20000)
authorize(2, "c1", "retail", 8000)  -> "a1"
capture(3, "a1", 6000)              -> true
refund(5, "a1", 2500)               -> true
refund(6, "a1", 4000)               -> false   (only 3500 left to refund)
refund(7, "a1", 3500)               -> true
balance(8, "c1")                    -> 0
available(8, "c1")                  -> 20000
statement(8, "c1")                  -> ["3:a1:charge:6000", "5:a1:refund:2500", "7:a1:refund:3500"]
```
