## Level 3: priorities, allowlist and explanations

Some customers are trusted and keep tripping the rules, and support needs to tell a merchant why a payment was stopped. Every rule now has a **name** and an integer **priority** (any integer, negative too):

- a blocklist entry is named `"block:<kind>:<value>"` (for example `"block:card:4111"`) and starts at priority 0;
- a velocity rule is named by its `{{rule_id}}` (rule ids never contain a colon) and starts at priority 0;
- a new **allowlist** entry, named `"allow:<kind>:<value>"`, matches like a blocklist entry but says `"approve"`.

Add:

| Method | Behaviour |
|---|---|
| `{{allow}}({{ts}}, {{kind}}, {{value}}, {{priority}}) → bool` | Puts `{{value}}` on the allowlist for `{{kind}}` (`"card"`, `"merchant"` or `"country"`) with that priority. Returns `false`, changing nothing, for any other `{{kind}}` or if it's already allowlisted for that kind. |
| `{{set_priority}}({{ts}}, {{rule}}, {{priority}}) → bool` | Sets the priority of the rule with that name: a blocklist entry, an allowlist entry or a velocity rule. Returns `false` if no rule has that name. |
| `{{explain}}({{ts}}, {{txn_id}}) → string` | The name of the rule that decided the transaction, recorded when it was screened. `""` if no rule decided it, or it was never screened. |

**Deciding.** Collect every rule that applies to the transaction: blocklist entries that match it (`"decline"`), velocity rules that fire (`"review"`) and allowlist entries that match it (`"approve"`). The rule with the **highest priority** decides. On equal priority the stricter outcome wins: `"decline"` over `"review"` over `"approve"`; if that still ties, the smallest name in plain string order. When no rule applies the decision is `"approve"`, decided by no rule.

- An entry taken off the blocklist (or a removed velocity rule) is gone with its priority: added again, it starts at 0.
- `{{remove_rule}}` still removes only velocity rules.
- Changing rules never changes a decision or explanation already recorded.

### Example

```
{{block}}(1, "merchant", "m-casino")                       → true
{{add_velocity_rule}}(2, "v-count", "count", 1, 600)       → true
{{allow}}(3, "card", "4111", 5)                            → true
{{screen}}(10, "t1", "4111", "m-casino", 1000, "GB")       → "approve"
{{explain}}(11, "t1")                                      → "allow:card:4111"   (5 beats the block's 0)
{{set_priority}}(12, "block:merchant:m-casino", 9)         → true
{{screen}}(13, "t2", "4111", "m-casino", 1000, "GB")       → "decline"
{{explain}}(14, "t2")                                      → "block:merchant:m-casino"
{{screen}}(15, "t3", "5500", "m-shoes", 1000, "GB")        → "approve"
{{screen}}(16, "t4", "5500", "m-shoes", 1000, "GB")        → "review"
{{explain}}(17, "t3")                                      → ""
{{explain}}(18, "t4")                                      → "v-count"
```
