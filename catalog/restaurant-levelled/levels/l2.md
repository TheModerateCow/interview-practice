## Level 2: the walk-in waitlist

Walk-ins who find the restaurant full want to wait for a table, and the host wants to see what's still free. Add:

| Method | Behaviour |
|---|---|
| `{{join_waitlist}}(ts, name, size, slot) → bool` | A walk-in party asks for a table at `slot`. If a table fits right now (the same rule as `{{book}}`), the party is booked straight away (next reservation id) and doesn't wait. Otherwise it joins the back of that slot's waitlist. Returns `false`, changing nothing, if `size <= 0` or `name` is already on that slot's waitlist. |
| `{{waitlist}}(ts, slot) → list of strings` | The slot's waitlist as `"name(size)"`, front first. An empty list if nobody is waiting. |
| `{{free_tables}}(ts, slot) → list of strings` | The ids of every table nobody holds at `slot`: fewest seats first, ties by table id ascending. |

**Seating from the waitlist.** When `{{cancel}}` frees a table, that slot's waitlist is walked front first: every waiting party that a table now fits (the `{{book}}` rule, against the tables still free at that point) is booked (next reservation id) and leaves the waitlist. A party that doesn't fit keeps its place, and parties behind it can still be booked. Each slot has its own waitlist. Adding a table doesn't seat anyone, and `{{book}}` ignores the waitlist.

### Example

```
{{add_table}}(1, "T1", 2); {{add_table}}(1, "T2", 4)
{{book}}(2, "maya", 4, 1140)                 → "r1"
{{book}}(3, "leo", 2, 1140)                  → "r2"
{{join_waitlist}}(4, "ana", 4, 1140)         → true
{{join_waitlist}}(5, "bo", 2, 1140)          → true
{{waitlist}}(6, 1140)                        → ["ana(4)", "bo(2)"]
{{cancel}}(7, "r2")                          → true
{{table_of}}(8, "r3")                        → "T1"    (ana doesn't fit T1, bo does)
{{waitlist}}(9, 1140)                        → ["ana(4)"]
```
