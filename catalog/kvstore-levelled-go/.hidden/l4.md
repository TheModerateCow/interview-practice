## Level 4: backups and history

Before a risky rollout the team takes a backup, and after an incident they ask "what was this set to at the time?". Add:

| Method | Behaviour |
|---|---|
| `Backup(ts int) string` | Saves every field that exists at `ts`, and returns the backup's id: `"b1"`, `"b2"`, `"b3"`, … in order. A backup of an empty store is fine. |
| `Restore(ts int, backupID string) bool` | Replaces the **whole** store with the backup's contents: fields created after the backup disappear, deleted or changed fields come back as they were. Returns `false`, changing nothing, if the backup doesn't exist. A backup can be restored any number of times; changes made after a restore never alter the backup. |
| `GetAt(ts int, key, field string, atTs int) (string, bool)` | What `Get` would have returned at time `atTs` (`atTs <= ts`): the field after every operation at or before `atTs`, with expiry judged at `atTs`. |

**TTLs across a restore.** A backup remembers how much time each field had **left** when the backup was taken. On restore, that time restarts from the restore: a field with 7 left at the backup expires 7 after the `Restore` call, even if it had already expired in between. Fields without an expiry stay without one. Fields that had expired before the backup aren't in it.

A restore is a change at time `ts` like any other: `GetAt` for times before it still sees the old values.

### Example

```
SetWithTTL(5, "lock", "owner", "node-1", 10)   (expires at 15)
Set(6, "lock", "zone", "z1")
Backup(8)                       -> "b1"          (owner has 7 left)
Set(9, "lock", "zone", "z2")
Restore(40, "b1")               -> true
RemainingTTL(41, "lock", "owner") -> 6           (now expires at 47)
Get(42, "lock", "zone")         -> "z1", true
GetAt(43, "lock", "zone", 20)   -> "z2", true
GetAt(44, "lock", "owner", 20)  -> "", false     (expired at 15)
GetAt(45, "lock", "owner", 40)  -> "node-1", true
```
