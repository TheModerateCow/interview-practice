## Level 4: keystrokes saved

The product team wants to know how much the autocomplete helps: for a query, the fewest keystrokes a visitor needs if they use it perfectly. Add:

| Method | Behaviour |
|---|---|
| `{{fewest_keystrokes}}({{target}}) → int` | The box starts empty. Returns the fewest keystrokes that make it show exactly `{{target}}` (1 to 30 letters; it need not be logged), using the log as it is now. |

Each keystroke is one of:

- **a letter**: appends it to the box text;
- **Backspace**: removes the last letter (does nothing on an empty box);
- **Tab**: replaces the box text with its suggestion (as in `{{suggest}}`); does nothing if there is none.

The suggestion is worked out afresh for whatever the box shows at each moment, so a Tab can lead to text whose own suggestion is something else again. Answers must come back quickly even when the log holds thousands of distinct queries.

### Example

```
{{import_log}}(["shoes", "shirts", "shoes", "shirt", "shirts", "shorts", "shirts"])   → 4
{{fewest_keystrokes}}("shirtless")            → 6
{{fewest_keystrokes}}("shirts")               → 1
{{fewest_keystrokes}}("shoe")                 → 4
{{fewest_keystrokes}}("zebra")                → 5
{{delete_query}}("shirts")                    → true
{{fewest_keystrokes}}("shirtless")            → 8
```

`"shirts"` is the most popular query, so Tab in the empty box shows it (1 keystroke); Backspace leaves `"shirt"` (2), then type `l`, `e`, `s`, `s` (6). Once `"shirts"` is deleted, the empty box suggests `"shoes"`: typing `s`, `h`, `i` and pressing Tab shows `"shirt"` (4), then four letters make 8.
