## Level 4: reschedules, hand-overs and history

Patients move appointments, clinicians go on leave and hand their list to a colleague, and the practice manager wants an audit trail. Add:

| Method | Behaviour |
|---|---|
| `Reschedule(ts int, id string, newStart int) bool` | Moves a `booked` appointment that hasn't started (`ts < start`) to `newStart`, keeping its clinician, patient and type. It needs `newStart >= ts`, the clinician free and a room free, ignoring the appointment's own old slot; the room is picked again by the usual rule. `false`, changing nothing, otherwise. The old slot is then offered to the waitlist at its old `start`, like a cancellation. |
| `HandOver(ts int, from, to string) ([]string, bool)` | Gives every `booked` appointment of `from` to `to`, in order of start time. One that would overlap an appointment `to` already has (including ones just handed over) is cancelled instead. Returns the cancelled ids in that order (empty, non-nil if none) and `true`. Appointments keep their rooms and times; ones already checked in, completed, cancelled or no-shows stay with `from`. Then `from`'s waitlist joins the back of `to`'s, in order, skipping patients already waiting for `to`, and `from`'s waitlist is emptied. `from` stays on staff. Returns `nil, false`, changing nothing, if either clinician doesn't exist or they're the same. A hand-over never books anyone from a waitlist. |
| `History(ts int, id string) []string` | Everything that happened to the appointment, oldest first, as `"time:event"` (empty, non-nil for an unknown id). |

**History events**, each dated when it happened:

| Event | When |
|---|---|
| `booked` | `Book`, or a booking from the waitlist (dated when the slot was freed) |
| `cancelled` | `Cancel`, or a clash in a hand-over |
| `checked-in` | `CheckIn`, or a waitlist booking after a no-show (same time as its `booked`) |
| `no-show` | at `start + 10`, even if the clinic only noticed it later |
| `rescheduled:<newStart>` | `Reschedule` |
| `handed-over:<to>` | `HandOver` |

Reaching `completed` isn't an event.

### Example

```
(dr-lee and dr-ng, one room room-1, types checkup 30 and review 20)
Book(10, "dr-lee", "pat-1", "checkup", 100)       -> "appt1", true
Book(11, "dr-ng", "pat-2", "review", 300)         -> "appt2", true
Reschedule(20, "appt1", 290)                      -> false      (room-1 is taken at 300)
Reschedule(21, "appt1", 200)                      -> true
HandOver(30, "dr-lee", "dr-ng")                   -> [], true
Schedule(31, "dr-ng")                             -> ["appt1@200-230", "appt2@300-320"]
History(400, "appt1")                             -> ["10:booked", "21:rescheduled:200", "30:handed-over:dr-ng", "210:no-show"]
```
