## Level 3: find a time for everyone

The **find a time** button: pick attendees and a meeting length, and the calendar proposes the first slot they can all make. Calendars are big (dozens of attendees, months of busy blocks, searches over a whole year), and blocks and profiles keep changing between searches, so each search must stay fast. Add:

| Method | Behaviour |
|---|---|
| `{{earliest_meeting}}({{ids}}, {{duration}}, {{from}}, {{to}}) → int` | The earliest UTC minute `t` with `{{from}} <= t` and `t + {{duration}} <= {{to}}` such that **every** attendee in `{{ids}}` is free (as in `{{is_free}}`) at every minute of `[t, t + {{duration}})`. `-1` if there is no such `t`, or if any id is unknown. |

- `{{ids}}` holds at least one id and no repeats; `{{duration}} >= 1`; `{{from}} < {{to}}`.
- A meeting can run across midnight, local or UTC, as long as everyone stays free: someone who works all day (`0, 1440`) or an overnight shift is free straight through midnight.
- Each search uses the calendar as it is at that moment, including blocks and profile changes made since the last search.

### Example

```
(ana: offset 0, hours 540-1020, busy 540-600)
(raj: offset 330, hours 540-1080 = UTC 210-750, busy 630-700)
{{earliest_meeting}}(["ana", "raj"], 30, 0, 1440)      → 600     (600-630 fits exactly)
{{earliest_meeting}}(["ana", "raj"], 45, 0, 1440)      → 700     (700-745)
{{earliest_meeting}}(["ana", "raj"], 60, 0, 1440)      → -1
{{earliest_meeting}}(["ana", "raj"], 60, 0, 2880)      → 1980    (09:00 UTC on day 1)
{{earliest_meeting}}(["ana", "zed"], 30, 0, 1440)      → -1
```
