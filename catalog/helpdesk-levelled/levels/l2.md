## Level 2: queues and auto-assignment

Agents want to see what to work on next, and new tickets should go to whoever is least busy. A ticket is **unresolved** while its status is anything but `"resolved"`. Add:

| Method | Behaviour |
|---|---|
| `{{queue}}(ts, agent) → list of strings` | The ids of `agent`'s unresolved tickets: `"high"` first, then `"normal"`, then `"low"`; within a priority, oldest ticket first (`"t9"` before `"t10"`). An empty list if the agent doesn't exist or has none. |
| `{{auto_assign}}(ts, ticket_id) → string` | Gives a ticket that has no agent yet to the agent with the fewest unresolved tickets (ties by agent name, ascending) and returns that agent's name. Returns `""`, changing nothing, if the ticket doesn't exist, already has an agent, or there are no agents. |

### Example

```
{{add_agent}}(1, "maya"); {{add_agent}}(1, "leo")
{{open_ticket}}(2, "acme", "low")       → "t1"
{{open_ticket}}(3, "globex", "high")    → "t2"
{{open_ticket}}(4, "initech", "low")    → "t3"
{{assign}}(5, "t1", "maya"); {{assign}}(5, "t2", "maya"); {{assign}}(5, "t3", "maya")
{{queue}}(6, "maya")                    → ["t2", "t1", "t3"]
{{open_ticket}}(7, "umbrella", "normal") → "t4"
{{auto_assign}}(8, "t4")                → "leo"   (leo has 0, maya 3)
{{open_ticket}}(9, "hooli", "high")     → "t5"
{{auto_assign}}(10, "t5")               → "leo"
{{queue}}(11, "leo")                    → ["t5", "t4"]
```
