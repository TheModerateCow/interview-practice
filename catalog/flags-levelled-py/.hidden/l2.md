## Level 2: percentage rollouts and queries

The team wants to release to a slice of users first, and to see which flags their services actually check. Add:

| Method | Behaviour |
|---|---|
| `set_rollout(ts, flag_id, env, percent) -> bool` | While the flag is on in `env`, only users whose bucket is **less than** `percent` see it. Every environment starts at `100`. Returns `False`, changing nothing, if the flag doesn't exist or `percent` isn't an integer from `0` to `100`. Setting a rollout on an off flag is allowed; the flag stays off. |
| `enabled_flags(ts, env, user_id) -> list[str]` | Ids of every flag `user_id` sees on in `env`, ascending. |
| `most_evaluated(ts, env, n) -> list[str]` | Up to `n` flags as `"flag_id(count)"`, where `count` is the number of `is_enabled` calls for that flag in `env` so far: most first, ties by flag id ascending. Only flags with at least one call in `env`. Calls for unknown flags and `enabled_flags` calls don't count. |

**Buckets.** A user's bucket for a flag is a stable number from 0 to 99:

```
key = flag_id + ":" + user_id
h = 0
for each character c of key:  h = (h * 31 + ord(c)) mod 1000000007
bucket = h mod 100
```

For example the bucket of `ana` for `"checkout"` is 36, and of `bo` is 53.

Targeted users always see the flag, whatever the rollout. Each environment has its own rollout.

### Example

```
create_flag(1, "checkout"); set_enabled(2, "checkout", "prod", True)
set_rollout(3, "checkout", "prod", 40)     -> True
is_enabled(4, "checkout", "prod", "ana")   -> True    (bucket 36)
is_enabled(5, "checkout", "prod", "bo")    -> False   (bucket 53)
most_evaluated(6, "prod", 5)               -> ["checkout(2)"]
```
