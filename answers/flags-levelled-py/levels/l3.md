## Level 3: scheduled changes

Launches are planned ahead: "switch the banner on in prod at 9:00". Add:

| Method | Behaviour |
|---|---|
| `schedule_change(ts, flag_id, env, on, at_ts) -> str` | Schedules the flag to be switched on or off in `env` at time `at_ts`, exactly as if `set_enabled(at_ts, flag_id, env, on)` had been called then. Returns the schedule's id: `"s1"`, `"s2"`, `"s3"`, … in order, counted across the whole service; a failed call uses no id. Returns `""`, changing nothing, if the flag doesn't exist or `at_ts <= ts`. |
| `cancel_schedule(ts, schedule_id) -> bool` | Cancels a pending change so it never happens. Returns `False` if the id is unknown, already cancelled, or already applied. |
| `pending(ts, flag_id) -> list[str]` | Ids of the flag's scheduled changes that are neither applied nor cancelled, in every environment: earliest `at_ts` first, ties in the order they were scheduled. Empty for an unknown flag. |

Nothing runs between calls, so due changes are applied as calls arrive: at the start of every method call, apply every pending change with `at_ts <= ts`, earliest first (ties in scheduling order), **before** the call itself runs. So a change due at `at_ts` is already applied, and can no longer be cancelled, during a call at `ts == at_ts`, and a `set_enabled` at that same time overrides it.

### Example

```
create_flag(1, "launch")
schedule_change(2, "launch", "prod", True, 10) -> "s1"
pending(3, "launch")                          -> ["s1"]
is_enabled(9, "launch", "prod", "ana")         -> False
is_enabled(10, "launch", "prod", "ana")        -> True
cancel_schedule(11, "s1")                      -> False   (already applied)
```
